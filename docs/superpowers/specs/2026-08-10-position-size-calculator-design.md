# 仓位计算器设计文档

日期：2026-08-10
状态：已获用户批准

## 背景与目标

用户要求新增一个仓位计算器页面，计算逻辑对齐
`https://infinityalgo.com/tools/calculators/position-size-calculator`。

**关于「一模一样」的边界，已向用户明示并获认可：**

- 实现的是**公开的标准风险管理算法**（对方自己把主公式印在页面上），不复制其
  界面、文案或代码；页面用站内既有设计语言重做。
- 核心算法与全部输出已由实测反推确认（见下），能做到逐位一致；但对方的舍入
  细节没有源码可依，极端输入下可能有末位差异。

## 已确认的现状事实

**外部计算器（2026-08-10 实测反推）。** 页面只公布了主公式
`Position Size = (Account Balance × Risk %) ÷ (Entry − Stop)`；以下全部是在
真实页面上驱动表单、读取输出反推得到的：

以 余额 10000 / 风险 2% / 入场 50 / 止损 48 / 杠杆 1:1 为例，实测输出：

```
Position Size 100.000 shares，$5,000.00 total value
Required Margin: $5,000.00 @ 1:1
Risk Amount $200.00 | Risk Distance $2.00 (4.0%) | Position Value $5,000.00
Account Risk 2.0% | Position Risk 4.0% | Margin Used 50.0%
Max Losses 50 | Buying Power 50.0%
```

由此确定：账户风险% = 风险额/余额；**持仓风险% = 风险额/仓位价值**（数值上等于
止损距离占入场价的比例）；保证金占用% = 所需保证金/余额；最多亏损次数 =
⌊余额/风险额⌋；「Buying Power」与「Margin Used」是同一个值。

再以 风险 6% / 杠杆 1:10 验证杠杆链路：实测 Margin Used 15%，与
`仓位价值 15000 ÷ 10 ÷ 余额 10000` 吻合。

**风险档位标签**（逐点扫描 0.5/1/1.5/2/2.5/3/3.5/4/4.9/5/5.5/8/12 实测）：

| 账户风险 | 标签 |
|---|---|
| ≤ 1% | VERY CONSERVATIVE |
| ≤ 2% | CONSERVATIVE |
| ≤ 3% | MODERATE RISK |
| ≤ 5% | HIGH RISK |
| > 5% | VERY HIGH RISK |

仪表刻度为 0 / 2 / 5 / 10%+。

**本项目现状（读码核实）：**

- 站内没有任何 `tools` 或 `calculator` 路由，不存在冲突。
- 桌面 `Navbar` 的 `USER_NAV_ITEMS` 是
  `["dashboard","videos","articles","news","trade","screener"]`。
- `src/lib/nav/tabs.ts` 的 `TAB_SEGMENTS.screener` 目前只有 `["screener"]`；
  `BACK_HIDDEN_SEGMENTS` 含 `screener`；`resolveBackTarget` 无 `tools` 分支。
- 项目 vitest 是 node 环境，`include` 只有 `src/lib/**` 与 `src/stores/**`——
  纯函数放 `src/lib/` 才测得到。

## 设计

### ① 纯计算核心

新建 `src/lib/position-size.ts`，导出一个纯函数
`computePositionSize(input: PositionSizeInput): PositionSizeResult`。
**所有算法集中在这里，UI 只收集输入与展示。** 这样「逻辑一模一样」是可被测试
证明的，而不是靠肉眼比对界面。

统一模型（四类资产共用）：

```
风险额     = 风险模式==='percent' ? 余额 × 风险%/100 : 风险金额
止损距离   = |入场价 − 止损价|                      （多空同样取绝对值）
每单位风险 = 止损距离 × 报价币→USD 汇率
数量(units)= 风险额 ÷ 每单位风险
仓位价值   = 数量 × 基础币→USD 汇率
所需保证金 = 仓位价值 ÷ 杠杆
```

四类资产只在两个「汇率」上不同：

| 资产 | 报价币→USD | 基础币→USD |
|---|---|---|
| 股票 / 加密 | 1 | 入场价 |
| 期货 | 合约乘数 | 入场价 × 合约乘数 |
| 外汇 | 见 ② | 见 ② |

股票/加密代入后即退化为 `数量 = 风险额 ÷ 止损距离`、
`仓位价值 = 数量 × 入场价`，与实测一致。

输出：`units`（外汇再换算成手数）、仓位价值、所需保证金、风险额、止损距离及其
百分比、账户风险%、持仓风险%、保证金占用%、最多亏损次数、风险档位。

### ② 外汇点值（美元账户，零外部依赖）

用户已确认**只支持美元账户**，因此只开放含美元的币对。这类币对的两个汇率都能
从入场价本身推出，不需要任何行情或汇率 API：

- **报价币是美元**（EUR/USD、GBP/USD、AUD/USD、NZD/USD）：
  报价币→USD = 1，基础币→USD = 入场价
- **基础币是美元**（USD/JPY、USD/CHF、USD/CAD）：
  报价币→USD = 1/入场价，基础币→USD = 1

点大小：日元报价的币对为 `0.01`，其余为 `0.0001`。一标准手 = 100,000 单位。
止损可填价格或点数，二者互算：`止损距离 = 点数 × 点大小`。

**交叉盘（如 EUR/GBP）不开放**——美元账户下它需要外部汇率，无法保证与对方一致。
这是刻意的范围边界，不是遗漏。

用外部页面自己的例子验证本模型：账户 5000、风险 1%（$50）、EUR/USD
入场 1.0850、止损 1.0800（50 点）。代入：每单位风险 = 0.0050 × 1 = $0.005，
数量 = 50/0.005 = 10,000 单位 = **0.1 手**，与其页面标注的 0.1 lots 一致；
仓位价值 = 10,000 × 1.0850 = $10,850。

### ③ 高级项（可选开关，关闭时对核心结果零影响）

- **止盈 → 盈亏比**：`R:R = |止盈−入场| / 止损距离`，并给出预期盈利
  `= 数量 × |止盈−入场| × 报价币→USD 汇率`
- **手续费 + 滑点**：两者都通过抬高「每单位风险」来**压低**仓位数量。

  这里有个必须绕开的循环：手续费若定义成「仓位价值的百分比」，而仓位价值又由
  数量决定、数量又取决于含手续费的风险额——方程自我引用，解不出来。**改为按
  单位摊算**，一次代数即可闭合：

  ```
  每单位手续费 = (入场价 + 止损价) × 手续费率/100 × 报价币→USD 汇率
  每单位风险   = (止损距离 + 滑点) × 报价币→USD 汇率 + 每单位手续费
  ```

  手续费取入场价与止损价之和，因为一次完整交易在这两处各收一次；滑点是价格
  单位，直接并进止损距离。两项都关闭时，公式退化为 ① 中的原式，核心结果零变化。
- **期货合约乘数**：并入 ① 表中的两个汇率

### ④ 页面与导航

路由 `src/app/[locale]/(app)/tools/position-size/page.tsx`，**公开可访问**
（不要求登录——这类工具是拉新入口，登录墙会挡掉它的主要价值）。

导航接入：

- 桌面 `Navbar`：`USER_NAV_ITEMS` 追加 `tools`
- `tabs.ts` `TAB_SEGMENTS`：`screener` 增加 `"tools"`——筛选器与计算器同属
  「交易辅助」，归一个 tab 比新开一个 tab 更合理，也避免底部 5 个 tab 变 6 个
- `tabs.ts` `resolveBackTarget`：新增 `case "tools"` 返回 `/{locale}/screener`
- 手机端：从筛选器页放一个入口进来
- 三语文案齐全（`nav.tools` 及计算器页自身的全部标签）

`BACK_HIDDEN_SEGMENTS` **不加** `tools`——它不是 tab 落地页，应当显示返回按钮。

### ⑤ 测试与验收

**单元测试**（`src/lib/position-size.test.ts`，纯函数全覆盖）：

- 用「已确认的现状事实」里那组实测值做基准断言：10000/2%/50/48/1:1 必须得出
  100 股、$5,000 仓位价值、$200 风险额、4.0% 持仓风险、50.0% 保证金占用、
  50 次最多亏损
- 杠杆 1:10 + 风险 6% → 保证金占用 15.0%
- 风险档位五档的边界值各一条（1 / 1.01 / 2 / 2.01 / 3 / 3.01 / 5 / 5.01）
- 做空（入场 < 止损）与做多得出相同的数量——距离取绝对值
- 外汇：EUR/USD 用外部页面的例子（→ 0.1 手、$10,850）；USD/JPY 一条（验证
  报价币→USD = 1/入场价 这条支路）；日元对点大小为 0.01
- 期货合约乘数生效
- 止盈 R:R、手续费+滑点压低数量各一条
- 边界：止损距离为 0 → 不产生 Infinity 而是返回「无效输入」；余额/风险为 0 或
  负数同样拒绝

**人工验收**：桌面与手机各打开一次页面，逐项对照上面那组实测值；确认未登录
可访问；确认底部高亮筛选器 tab、返回按钮退到 `/screener`；三语各看一次。

## 明确不做（YAGNI）

- 不复制对方的界面、文案或代码
- 不做实时行情 / Live Market Data
- 不做保存/读取计算、快捷键、自动草稿
- 不做多币种账户与汇率 API（用户已选定美元账户）
- 不做交叉盘外汇（需要外部汇率，无法保证一致）
- 不做「实际交易所保证金」模式（依赖各交易所规则）
- 不做其余计算器（点值、盈亏、止损等）
